How the work flows

  1. Load each export with a small config file
  2. Match every alert to a core banking customer
  3. Send unsure matches to a short review queue
  4. Group alerts into one case per customer
  5. Rank cases and plan staffing to the deadline

Step 1

Data onboarding

Each system exports alerts differently: different IDs, date formats, money formats and name order. Instead of custom code per bank, each source gets a short config file that says which column means what. Every row read is accounted for, so nothing disappears quietly.

Step 2

Customer matching

An alert is only useful once you know whose it is. Matching tries the strongest evidence first. Anything below confidence is not guessed: it goes to a person.
